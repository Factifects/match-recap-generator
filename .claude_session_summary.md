## Goal

Techijest video: **"Why Does Your Browser Use So Much RAM?"** — 16:9, cool
machine-grey visual world (deliberately distinct from every prior episode's
warm paper). Two signature objects: a laptop/browser the camera can push
through, and a memory workspace (wall of blocks) that fills, crowds, and
reclaims. Colour = tab identity (YouTube red, Gmail blue, News green), reused
identically in the memory wall so "which tab is eating memory" is answered by
looking, never a legend.

## What is BUILT and PROVEN (rendered + visually confirmed)

All in `src/video/compositions/SpatialStage.tsx` (the 3D `Scene Type: Spatial`
medium) plus schema in `src/model/visualDefinitions.ts` and 2D counterparts in
`src/video/compositions/StageCard.tsx` / `src/script/stageLayout.ts`:

- **`laptop`** kind — real 3D machine, live browser painted on the screen via
  canvas texture (`useScreenTexture`). Camera can dolly THROUGH the screen
  (needed `distance` min lowered from 0.5 to 0.02 in schema, and an
  `intentionalPush` exception so auto-framing doesn't hold the camera back).
- **Camera focus now INTERPOLATES between keyframes** instead of snapping —
  this was a big fix so one continuous camera move (laptop → through screen →
  reveal) doesn't have to be split across scenes (which read as a jump-cut).
  `focusOffset` field added so a push can aim at a sub-part of an object (e.g.
  the tab strip, not the object's origin).
- **`tabCard`** kind — an open tab as a coloured card with its own title,
  painted via canvas texture, `extrude` action to arrive, `destabilise` action
  (0→1) to visibly fail: judders, drains colour, tilts — BEFORE anything dies.
  This was built to replace a "peeling browser" concept that was tried and
  explicitly rejected by the user as looking like a mess (overlapping
  rectangles — a browser window has no meaningful "inside" to peel open).
- **`memory`** kind — the memory workspace. A WALL (stood up to face the
  viewer, not a floor — floors needed a top-down camera that fought the
  browser's face-on camera). Blocks are coloured BY TAB (`accent` per region),
  not by state — state (`active`/`reusable`/`reclaimable`) changes how a block
  is TREATED (breathing/calm/hollow) and free space reddens under memory
  pressure. Sized to a fixed target width regardless of `capacity` (more
  capacity = finer blocks, not a bigger object — this was a real bug, fixed).
  `allocate` action re-shapes regions over time (grow/shrink/hand back).
- **`decode`** kind — small file card that opens into a dealt-out grid of
  pixels (image decode: file size on disk ≠ decoded size in memory).
- Headline sizing bug fixed: was based on frame WIDTH (so 16:9 headlines were
  ~2x too big vs portrait) — now based on `Math.min(width, height)` in both
  the 3D and flat renderers.
- Headline vs subtitle collision fixed: headline band is now a full opaque
  strip of the ground colour (not a soft gradient scrim, which couldn't fix
  red-headline-on-red-memory-block clashes), and it's offset so it doesn't sit
  in the same band as the spoken-word subtitle.
- Reduced headline (`beat`) frequency — was firing on every single narration
  beat and reading as a second subtitle; now used sparingly as punctuation.

Three throwaway proof scripts still in `analyses/` document the exact working
JSON for each proven piece (kept as reference, not meant to survive):
`_laptop-proof.txt` (laptop + tab reveal + per-tab cost bars),
`_crash-proof.txt` (process isolation / destabilise), `_decode-proof.txt`
(image decode). These were each rendered and visually confirmed correct.
