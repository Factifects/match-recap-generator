### SCENE 4

**Scene Type:** Canvas

**Narration:** Here's a distinction computer science genuinely cares about. Concurrency just means managing several tasks that are all in progress — they might still be taking turns. Parallelism means those tasks are physically executing at the exact same instant. One core alone can handle concurrency. Real parallelism needs more than one core.

**Narration:** And which thread actually gets to run next isn't random — it's decided by a scheduler, and different operating systems make genuinely different calls. Linux uses something called the Completely Fair Scheduler, built to give every thread a mathematically fair slice of time. Windows instead leans on priority, where more important threads simply get to run first.

### SCENE 7

**Scene Type:** Canvas

**Narration:** But sharing memory between threads is exactly where things can go wrong. If two threads both try to change the same value at the same time, you get what's called a race condition — the result depends entirely on which one happens to finish first, and that's rarely what anyone intended. The fix is a lock, forcing threads to take turns instead of colliding.
